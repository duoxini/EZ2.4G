# K99 V3 2.4G 卡顿排查记录

日期：2026-10-22。

## 已知情况

- 用户描述：2.4G 下长期存在无响应、短暂停顿后连续响应，使用有线规避；问题早于本电量工具，与工具无关。
- 本机只读 PnP 检查：3837:3033 接收器存在，状态 OK；其父设备为通用 USB 集线器 ASM107x（174C:2074），上游为 USB ROOT_HUB30。这说明当前接收器经过集线器，不说明集线器故障，也不证明接收器实际工作在 USB 3.x 速率。
- 状态 OK 仅代表当前枚举正常；没有录到卡顿发生时的输入、断连或无线数据，尚未确定根因。

## RSSI 能否读取

检查已有官方资源副本 `main.504a955bfd84363d1e76.js` 与 `index-D4Ndmk6J.js`，未发现 RSSI、LQI、signalStrength、packetLoss 等字段；当前已核实的 K99 GLW 配置读取只用于电量与充电状态，没有找到可验证的无线信号质量读取接口。

这是本次已检查资源的结论，不等于硬件内部不存在这些指标。不能将其他配置字节猜成 RSSI，也不能用电量查询耗时或 Windows Wi-Fi 信号替代键盘无线 RSSI。暂不添加无协议依据的设备命令。

## 建议的单变量对比

每步在同一个应用、同一段打字场景下比较约 5–10 分钟，记录卡顿次数和是否只发生在键盘上；其余条件保持不变。

1. 优先绕过当前集线器，接收器改为主机直连端口；有条件时用 USB 2.0 延长线把接收器移近键盘，远离机箱金属遮挡、其他接收器和高速 USB 设备。分别比较端口与摆放变化，避免一次换多个条件。
2. 如果仍有问题，再逐个暂时移开相邻无线接收器或 USB 3.x 高速设备，比较发生频率。
3. 再比较有线和 2.4G：若有线稳定、无线受位置影响明显，支持无线链路/接收器环境方向；若同一时刻鼠标、音频和其他程序也卡，需排查主机负载、USB 或驱动延迟。
4. 若换端口和位置均无改善，可在官方 M HUB 中记录当前无线回报率，再单独降低回报率比较。当前未读取或修改该设置，不能预设已经启用 8K。

本轮没有修改设备设置、回报率、配对、固件、系统电源或网络设置。实际对比需用户操作后才能继续判断。

## 依据

- [MCHOSE 官方 K99 系列故障排查](https://support.mchose.store/hc/en-us/articles/52491715289620-MCHOSE-K99-V3-K99-V2-K99-V1-FAQ-Troubleshooting-Guide)：2.4G 不稳定时建议换端口、直接连接电脑，避免紧邻其他接收器或高带宽 USB 设备。
